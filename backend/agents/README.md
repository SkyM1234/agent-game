# Agent 策略说明

本文说明当前项目中全部五种可选策略，涵盖决策流程、输入、评分、错误处理与评测边界。策略 ID 以 [scripted.py](./scripted.py) 的 `AGENTS` 和 [live.py](../matches/live.py) 的 `AGENT_IDS` 为准。

## 1. 策略总览

| 策略 ID | 页面名称 | 实现入口 | 决策方法 | 模型调用 |
| --- | --- | --- | --- | --- |
| `test` | 测试 | `TestAgent`，见 [scripted.py](./scripted.py) | 按配置顺序轮流尝试技能和道具 | 无 |
| `heuristic` | 规则机器人 | `HeuristicAgent`，见 [heuristic.py](./heuristic.py) | 按资源、距离和攻击效率执行固定优先级规则 | 无 |
| `counterfactual` | 反事实推演 | `CounterfactualRolloutAgent`，见 [planning.py](./planning.py) | 在引擎副本中模拟动作组合，按风险加权收益选择 | 无 |
| `deepseek` | 纯 DeepSeek | `DeepSeekAgent`，见 [deepseek.py](./deepseek.py) | 根据当前观察与历史，调用一个合法技能工具 | 有 |
| `counterfactual_deepseek` | 反事实推演 + DeepSeek | `DeepSeekAgent` + [live.py](../matches/live.py) 中的协调逻辑 | 先推演，再由模型参考候选信息选择；特定终局直接执行引擎推荐 | 通常有，满足直接执行条件时跳过 |

`test` 用于检查功能。其余四种策略组成当前对照评测的策略集合。

`deepseek` 与 `counterfactual_deepseek` 共享同一个模型适配类；两者的差异由对局协调层控制，不是两个独立模型客户端。

## 2. 所有策略共用的执行约束

### 2.1 同步观察与权威结算

每个决策回合先从同一份世界状态生成双方观察，再收集需要行动的角色的决策，最后统一提交给 `Arena.advance()`。模型请求期间不推进模拟时间。

观察包含自身和对手的位置、资源、动作状态、冷却、道具、技能规则、可用动作及来袭攻击。策略只提出动作，资源扣除、位移、碰撞、命中和胜负都由 [engine.py](../game/engine.py) 结算。

动作能否再次决策取决于 `windup_ms + recovery_ms`。超过该锁定时长仍未结束的效果可继续存在；角色不是每个回合都必然产生新决策。

### 2.2 合法动作与工具名称

引擎内部技能 ID 为 `jab`、`heavy_punch`、`kick`、`guard`、`dash`、`move`、`rest`，另有通用道具动作 `use_item`。这些内部 ID 复用于不同人物，并不表示人物在画面上使用同名招式。

模型通过 [character_tools.py](./character_tools.py) 使用人物专属工具名，例如 `blade_flurry`、`ice_bolt`；服务端将工具调用映射回内部 `Action`。工具参数受到当前资源、冷却、方向、合法传送区间及可用道具枚举约束。人物工具配置还可进一步收窄参数枚举。

本地策略直接读取引擎提供的合法动作；模型读取动态生成的 Tool Schema。最终提交的动作仍需经过引擎校验。双方同时选择相冲突的传送落点时，单方观察下合法的动作也可能被统一取消。

### 2.3 模型保底与引擎保底的区别

模型调用失败时，模型适配器尝试返回 `rest`，并标记 `source="fallback"`。如果此时恢复技能也在冷却，或者其他策略提交了非法动作，引擎会拒绝该动作并使用内部无效果动作 `idle`。

因此，“触发保底”不保证实际恢复了资源。`idle` 是引擎内部动作，不是供 Agent 正常选择的技能。

## 3. `test`：功能测试策略

### 决策顺序

1. 首次行动时，按 `observation.rules.skills` 的顺序保存技能列表，同时记录携带的道具 ID。
2. 每次成功选择一个技能后，下一次决策优先尝试尚未测试且当前可用的道具。
3. 选择道具后，将该道具 ID 从待测试列表移除。即使道具有多次使用机会，这个策略也只主动测试该 ID 一次。
4. 没有可测试道具时，从技能游标继续循环，跳过当前不可用技能，选择第一个可用技能。
5. 所有技能都不可用时返回 `rest`，之后仍由引擎校验。

有方向参数的技能优先使用 `forward`，否则使用合法枚举中的第一个方向。传送优先尝试落在对手靠近自己的一侧、距离对手 2.5 的位置；将坐标限制在边界内后，依次尝试该位置、自身位置、区间最小值和最大值，选择第一个合法坐标。

### 用途与限制

用于检查技能能否施放、道具效果、角色动画、回放与接口流程。它不根据射程选择攻击，不优化胜率，也不会预测对手。因此不能把战胜 `test` 当作策略能力显著提升的证据。

`export_state()` / `restore_state()` 保存和恢复技能游标、待测试道具及道具尝试标记，保证断点续局保持原来的轮换进度。

## 4. `heuristic`：固定规则机器人

每次决策从下表第一行开始，执行第一个满足条件的动作。

| 优先级 | 条件 | 动作 |
| --- | --- | --- |
| 1 | 存在当前可用的恢复道具，且它能恢复的至少一种资源低于该资源上限的 45% | 使用第一个符合条件的道具 |
| 2 | `jab`、`heavy_punch`、`kick` 中存在当前可用且射程覆盖对手的技能 | 选择攻击效率最高的技能 |
| 3 | 没有在上一步选出攻击，且体力 `<20` 或魔力 `<10`，并且 `rest` 可用 | 恢复资源 |
| 4 | 距离 `>3`，且 `dash` 可用，参数合法 | 向前冲刺，或传送至预定接近位置 |
| 5 | `move` 可用且允许 `forward` | 向前步行 |
| 6 | 前述条件均未选出动作 | 按固定顺序寻找合法兜底动作 |

攻击效率的计算为：

```text
攻击效率 = health_damage / max(1, windup_ms + recovery_ms)
```

分母单位为毫秒，`max(1, ...)` 用于避免除零。比较的是配置伤害与决策锁定时长，未计算真实命中率、弹道飞行时间、耗蓝或技能的长期冷却收益。评分相同时，按 `jab`、`heavy_punch`、`kick` 的顺序保留先出现的技能。

攻击优先于恢复：资源低并不必然休息，只要存在可用且当前够得着的攻击，就先攻击。道具阈值使用资源上限的比例；主动恢复的 20 点体力和 10 点魔力阈值则是绝对值。

传送时，目标距离为：

```text
目标距离 = max(1, jab.reach × 0.8)
目标坐标 = 对手坐标 − 朝向对手的符号 × 目标距离
```

落点位于对手靠近自己的一侧。该策略只测试这个目标坐标，不主动搜索绕后位置；如果坐标不合法，则继续检查步行和兜底规则。

兜底顺序为 `rest → guard → jab → heavy_punch → kick → move → dash → use_item`。只考虑可用动作，枚举参数取第一个值，位置参数尝试自身坐标，校验通过后返回；没有合法选项则抛出异常。

### 用途与限制

这是一个无历史状态、无模型调用、无前瞻模拟的确定性基线。它能接近、攻击、补资源和使用恢复道具，但没有主动躲避来袭攻击、预测对手或多步战术规划；防御只可能在兜底阶段被选中。

其目的是提供一个比轮流施放技能更合理的基础对手，不代表充分调优的传统游戏 AI。

## 5. `counterfactual`：反事实推演策略

### 5.1 生成候选动作

`CounterfactualRollout.candidate_actions()` 从当前合法工具生成有限动作集合：

- 无参数技能：每个技能一个候选。
- 方向技能：每个合法方向一个候选。
- 道具：每个可用道具 ID 一个候选。
- 传送：从边界、自身位置、合法区间端点与中点、攻击射程附近及对手身后等位置生成采样点；校验、去重后按离自身的距离排序，最多保留 5 个。

若对手当前不能决策，对手候选为 `None`，表示不提交新动作、继续已有动作。否则生成对手自己的候选集合。

**传送坐标是有限采样，不能理解成穷举了连续空间内所有合法落点。**

### 5.2 在引擎副本中模拟

对“自身候选 × 对手候选”的每个组合：

1. 克隆当前 `Arena`，保留资源、冷却、道具、在途攻击及其他战斗状态。
2. 同时提交双方候选并调用一次 `advance()`。
3. 如果双方都还不能决策，则继续推进，直到有人可以决策、对局结束，或达到推演时长条件。
4. 比较分支前后的状态，计算收益。

推演按决策间隔推进，默认 `max_rollout_ms=5000` 是模拟时间的循环停止条件，不是 CPU 时间预算；由于先推进且按间隔检查，不能把它理解成精确的 5 秒硬截断。

这是到下一个可决策事件附近的短期模拟，没有递归搜索多层后续决策。克隆分支不会改变正在运行的对局。

### 5.3 分支评分

默认权重位于 `UtilityWeights`：

| 指标 | 默认权重 | 对评分的影响 |
| --- | --- | --- |
| 对手生命减少量 | 1.0 | 正向，按对手剩余生命比例调整 |
| 自身生命减少量 | 1.2 | 负向，按自身剩余生命比例调整 |
| 自身体力变化 | 0.06 | 增加为正，消耗为负 |
| 自身魔力变化 | 0.09 | 增加为正，消耗为负 |
| 自身护盾变化 | 0.65 | 增加为正，消耗为负 |
| 位置价值变化 | 0.45 | 越接近偏好攻击距离越有利 |
| 自身剩余冷却总量变化 | 0.8 | 新增冷却负担扣分 |
| 未结算攻击压力差的变化 | 0.55 | 自身压力相对对手增加则加分 |
| 行动先手 | 1.5 | 自身可决策记 +1，对手可决策记 −1，再乘权重 |
| 道具储备消耗 | 0.25 | 消耗自己的道具扣分，消耗对手的道具加分 |
| 自身动作被拒绝次数 | 20.0 | 每次扣分 |

生命相关权重使用分支开始时的状态：

```text
实际权重 = 基础权重 × (2 − clamp(当前生命 / 生命上限, 0, 1))
```

生命越低，对应的生命损失越受重视。指标中的“伤害”由前后生命差计算，因此期间的治疗会抵消生命损失，它不是逐事件伤害总和。

位置价值为 `−abs(双方距离 − 自身最大攻击射程)`。未结算攻击压力根据伤害、当前阶段和朝向/距离启发式估计，前摇阶段系数为 0.35，生效阶段为 0.7；该值不是实际命中概率。

单件道具的储备价值估计为：

```text
生命恢复 + 0.06 × 体力恢复 + 0.09 × 魔力恢复
+ 0.65 × 护盾 + 5 × 冷却减少回合 + 1.5 × 后退距离
```

如果模拟分支已经结束，自身获胜额外加 10000 分，败北额外扣 10000 分，平局没有额外终局分。时间耗尽导致的胜负也参与此评分。

### 5.4 跨对手应对进行风险加权

对于每个自身动作，汇总所有采样对手应对的分支评分：

```text
动作评分 = risk_aversion × 最低分 + (1 − risk_aversion) × 平均分
默认 risk_aversion = 0.7
```

最低分代表最坏采样应对，平均分是所有采样应对的等权平均；没有根据对手历史预测各动作发生概率。

同一位置技能的多个落点在评分后只保留其中最强的一个，再与其他动作比较。最终按动作评分、平均分、动作键长度与动作键字典序打破平局，保证排序确定。

### 用途与限制

该策略可以利用权威规则计算短期伤害交换、资源消耗、冷却与道具价值，适合用来检验模型是否在纯搜索基础上带来增益。

它需要 `decide_in_arena(arena, player)`，不能只调用 `decide(observation)`。它能读取完整引擎状态，模型则读取结构化观察，因此对照结果也包含信息表示差异。候选数量增加时，分支计算量随双方候选数的乘积增长。

结果依赖人工权重、有限传送采样和短期视野，不保证全局最优。更多推演细节见 [反事实推演设计](../../docs/counterfactual-planning.md)。

## 6. `deepseek`：纯模型工具调用策略

### 6.1 模型收到什么

`prompt_messages()` 将信息拆成两部分：

| 消息 | 内容 |
| --- | --- |
| `system` | 通用战斗规则、当前人物提示词、固定 `match_context`，包括双方人物、武器、资源上限、有效技能数值和道具配置 |
| `user` | 当前双方资源、位置、动作阶段、剩余锁定/效果时间、冷却、来袭攻击、剩余比赛时间、最近回合与历史聚合 |

对局协调层保留最近 4 个决策周期的动作、事件及状态变化，更早记录聚合为 `opponent_history`，包括动作、方向、道具、结果次数和造成的伤害。该聚合不保留完整时间顺序，也不是长期记忆或学习后的策略参数。

历史中的 `decision_summary` 不回填给模型。当前可用工具通过请求中的 Tool Schema 提供，不重复附带整份不可用工具列表。

纯模型路径不调用 `CounterfactualRollout.analyze()`，不接收 `counterfactual_analysis`，也不会触发混合策略的终局直接执行分支。

### 6.2 输出与校验

通过 HTTPX 请求 `/chat/completions`，要求调用工具，关闭流式输出，并发送 `thinking: {"type": "disabled"}`。

返回必须恰好包含一个 `function` 工具调用，工具名必须当前可用，参数集合、类型、枚举、数值范围和传送排除区间都要通过校验。服务端将其转换成内部 `Action`。

工具 Schema 要求附带最多 60 字的 `decision_summary`。实际解析时，摘要缺失或类型错误会变成空字符串，超长内容会截断；只要动作合法，不因摘要本身丢弃动作。该摘要用于展示，不能当作真实推理过程或行为正确性的证明。

### 6.3 修正、保底与停止

- 工具名、参数或响应结构不合法时，在同一次决策的总超时预算内，附上具体错误后最多再请求一次。
- 超时、连接错误、限流或服务端错误会走保底；并非所有错误都会重试。
- 普通失败返回 `rest` 并记录原因；恢复是否实际生效仍由引擎校验。
- 连续模型保底次数达到阈值时，由对局协调层停止对局，默认阈值为 3。任一非保底决策会重置连续失败计数。
- HTTP 400、401、402、403、404 被映射为请求配置、鉴权、余额或模型不可用错误，直接上抛，不假装完成一场正常对局。

### 6.4 配置默认值

以下为代码默认值，实际运行以项目根目录 `.env` 和传入的设置为准：

| 环境变量 | 默认值 | 含义 |
| --- | --- | --- |
| `DEEPSEEK_MODEL` | `deepseek-v4-flash` | 请求模型名 |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | 接口根地址 |
| `DEEPSEEK_TIMEOUT_SECONDS` | 20 | 单次决策总请求预算，包含参数修正请求 |
| `DEEPSEEK_MAX_TOKENS` | 512 | 每次请求的输出上限 |
| `DEEPSEEK_TEMPERATURE` | 0.5 | 采样温度 |
| `DEEPSEEK_MAX_CONSECUTIVE_FAILURES` | 3 | 连续保底停止阈值 |

密钥使用 `DEEPSEEK_API_KEY`；不应写入人物提示词、回放或文档。当前通用提示词版本为 `combat-tools-v16`。

### 用途与限制

该策略用于观察模型在没有引擎推演提示时的决策能力。模型输出可能变化，网络请求增加现实等待时间和费用；合法工具约束能限制非法调用，但不能保证战术质量。

## 7. `counterfactual_deepseek`：推演与模型结合

每次需要决策时，先运行与纯推演策略相同的 `CounterfactualRollout`。之后有两条路径。

### 7.1 满足终局条件时直接执行

检查引擎当前推荐动作对应的全部采样应对分支：

- 每个分支都已经结束。
- 结果都相同：全部胜、全部负，或全部平。
- 结束原因全部为 `knockout` 或 `double_knockout`。

满足条件时直接执行推荐动作，记录 `source="counterfactual"`，本次不请求模型。这同时覆盖必胜、必败、必平的击倒分支，不只覆盖必胜。

仅评分领先、候选分差很大，或通过时间耗尽判出的胜负，不触发该捷径。“全部应对”只指当前生成的有限候选集合与推演范围，并非对连续动作空间和整场比赛的数学保证。

### 7.2 其余情况由模型参考推演结果选择

模型除第 6 节的公共输入外，还收到 `counterfactual_analysis`：候选动作、相对偏好、最坏采样应对、终局状态，以及默认评分前三个候选的最坏分支指标。

内部风险加权分转换为当前候选集合内的相对偏好：

```text
preference = 100 × (当前候选评分 − 最低评分) / (最高评分 − 最低评分)
```

所有评分相同时，每个候选的偏好都为 100。候选按动作键排序发送，不直接发送 `recommended_action`、原始推荐分数或推荐分差。**偏好不是胜率，不能跨回合比较。**

模型仍从当前合法 Tool Schema 中选择一个工具，不被强制绑定到引擎排名第一的动作。传送提示只保留推演筛选后的最佳采样落点，但工具参数仍允许合法区间内的其他坐标，因此模型可以选择未被推演展示的落点。

返回后，记录引擎推荐动作和推荐分数，方便与模型实际选择对比。如果模型失败，沿用第 6 节的恢复保底；当前实现不会自动改为执行推演推荐动作。

### 用途与限制

该方案把短期模拟结果提供给模型，同时保留模型结合历史和人物提示词选择动作的空间。它同时承担推演计算与模型请求的成本，也可能受到人工评分偏差的影响。

评测时需要与纯推演和纯模型分别比较。由于该方案含有终局直接执行逻辑，测量到的是完整混合方案的效果，不能把全部变化都归因于“多了一段推演提示”。

## 8. 诊断记录与评测解释

在 `record_live_match()` 路径中，`DecisionInfo` 记录以下信息：

| 字段 | 含义 |
| --- | --- |
| `source` | `script`、`counterfactual`、`llm` 或 `fallback`；表示本次实际决策来源，不一定等于整局策略 ID |
| `attempts` | 本次决策的模型请求尝试次数，修正请求也计数 |
| `latency_ms` | 模型适配器内部的请求与修正耗时 |
| `decision_latency_ms` | 本策略决策耗时，包含适用的推演和模型等待，不含动画与存档写入 |
| `prompt_tokens` / `completion_tokens` / `total_tokens` | 服务端返回的用量累计，包含修正请求中已获得的用量 |
| `requested_model` / `returned_model` | 请求模型名与响应模型名 |
| `errors` | 请求、解析或参数错误 |
| `rollout_recommendation` / `risk_weighted_score` | 适用时记录引擎推荐动作及其评分 |

无模型调用的本地决策，`attempts` 和 Token 为零；纯模型的保底可能出现 `source="fallback"`；混合策略跳过模型时会出现 `source="counterfactual"`。分析数据时应同时查看策略 ID 和决策来源。

有 `ReplayStore` 的对局路径还会写独立回合诊断日志；当前批量评测先生成完整回放后保存，报告保留逐场指标与配置，不自动保存完整模型请求日志。回放播放不重新运行 Agent。

评测报告中，胜率、动作指标、延迟与用量均按文档规定的统计口径计算；失败场次单独显示。固定规则与纯推演的重复运行不会增加独立样本，模型则需要重复采样。不能用少量固定局面或单一对手的结果宣称通用胜率。

## 9. 运行与配置入口

以下命令在项目根目录、已安装依赖的 Python 环境执行：

```powershell
# 单场本地对照
python -m backend.matches --p1 heuristic --p2 counterfactual --json

# 单场模型对照：需要有效密钥，会产生模型用量
python -m backend.matches --p1 deepseek --p2 counterfactual_deepseek --json

# 批量本地评测：默认规则机器人 vs 反事实推演
python -m backend.evaluation

# 四组策略对照：会产生真实模型用量
python -m backend.evaluation --include-llm

# 指定纯模型与混合策略，复用一次实验的配置快照
# 将 <run_id> 替换为实际报告目录名
python -m backend.evaluation --include-llm --strategies deepseek counterfactual_deepseek --suite data/evaluations/<run_id>/report.json
```

单场命令使用 `--config` 读取 `GameConfig` JSON；不提供时使用默认配置。批量评测默认加载绯刃与霜铃，每次只使用一个距离局面，初始中心距离默认为 6，可用 `--distance 3.5` 调整（范围 0.8～11.2），交换角色并镜像出生位置。`--distance` 与 `--suite` 互斥；`--suite` 只接受单局面配置或报告。不同入口的默认配置不完全相同，比较结果时应核对配置快照。

| 要调整的内容 | 入口 |
| --- | --- |
| 功能测试轮换顺序与行为 | [scripted.py](./scripted.py) |
| 规则机器人优先级、阈值与传送位置 | [heuristic.py](./heuristic.py) |
| 推演评分、风险偏好、候选采样和视野 | [planning.py](./planning.py) |
| 模型通用提示词、请求参数和响应校验 | [deepseek.py](./deepseek.py) |
| 人物专属提示词、工具和技能数值 | [configs/characters](../../configs/characters/) 下的 `prompt_neutral.md`、`prompt_aggressive.md`、`tools.json`、`character.json` |
| 模型观察压缩、人物工具名映射 | [character_tools.py](./character_tools.py) |
| 策略分流、历史窗口、直接执行捷径与连续失败停止 | [live.py](../matches/live.py) |
| 评测局面、调度和汇总指标 | [evaluation/runner.py](../evaluation/runner.py) |

修改提示词、评分权重或规则后，应创建新评测，并保留模型参数、人物配置、规则版本和后端源码摘要。报告配置快照只能固定输入；复跑时还需核对代码版本与模型设置。

# 战斗回合与时间说明

当前战斗采用双方同时决策的方式。默认每回合推进 **0.5 秒游戏模拟时间**，技能的前摇、生效和后摇则按各自配置的时长执行，因此一个技能可能持续多个回合。

本文中的数值以当前默认配置为例；修改对局或人物配置后，以该对局保存的配置为准。

## 1. 战斗时间与现实时间

**战斗时间是游戏内部的模拟时间，不是现实中经过的时间。**

例如，游戏当前停在第 10 秒，模型思考花了现实中的 3 秒。在这 3 秒内，游戏仍停在第 10 秒。双方决策完成后，正常推进一回合，游戏时间才到 10.5 秒。

模型思考期间：

- 人物不会继续移动。
- 冰弹等飞行攻击不会继续飞行。
- 技能前摇、生效、后摇都不会继续推进。
- 技能冷却不会减少，资源不会继续恢复。

双方模型可以并发思考，系统收齐本回合所需的决策后再统一推进。模型请求超时也不会额外消耗游戏时间：系统按错误处理规则执行休息保底，或在连续失败等情况下停止对局。

因此，游戏内 60 秒的对局，现实中可能持续几分钟。实际耗时还取决于模型响应、播放速度和手动暂停。

## 2. 一个回合如何运行

每回合按以下顺序执行：

1. 从同一时刻的战场状态生成双方观察。双方看不到对方本回合尚未提交的选择。
2. 空闲角色以及已经度过“前摇 + 后摇”锁定时间的角色选择技能；仍在锁定中的角色无需重新请求模型。
3. 校验并同时提交双方动作。
4. 推进最多 0.5 秒模拟时间，期间计算移动、飞行、命中、伤害与恢复。
5. 若对局尚未结束，进入下一回合，更新剩余冷却回合数。

双方都处于动作锁定时，也会继续推进回合。如果某人在回合中途被击倒，或达到游戏时间上限，则立即结束，不必走满 0.5 秒。

默认每个回合内部拆成 10 个 **0.05 秒的模拟步**。移动和命中会在这些小步中结算，双方同一步产生的伤害统一处理。

## 3. 动作锁定与技能冷却

这两种限制独立存在：

| 限制 | 含义 | 影响范围 |
| --- | --- | --- |
| 动作锁定 | 当前动作经过的时间还没有达到 `windup_ms + recovery_ms` | 不能提交新的决策 |
| 技能冷却 | 某个技能施放后，需要等待若干回合才能再次使用 | 只限制该技能，其他合法技能仍可选择 |

技能的冷却结束后，如果人物的“前摇 + 后摇”锁定时间还没有结束，就仍然不能选择新动作。反过来，动作锁定结束，也不代表该技能的冷却已经结束。

`active_ms` 只控制技能效果持续多久，不增加决策锁定。到达回合决策点时，只要当前动作已经经过 `windup_ms + recovery_ms`，模型就能选择新动作并立即启动；仍未结束的旧效果会继续独立结算，并出现在观察的 `ongoing_actions` 中。

## 4. 冰弹跨回合示例

当前霜铃的冰弹配置：

- 前摇：0.25 秒。
- 生效：0.6 秒，期间进行弹道飞行和命中判定。
- 后摇：0.2 秒。
- 决策锁定：0.25 + 0.2 = 0.45 秒。
- 冰弹效果结束：施放后 0.85 秒。

假设霜铃在第 1 回合开始时释放冰弹：

| 回合 | 游戏时间区间 | 霜铃的动作 |
| --- | --- | --- |
| 第 1 回合 | 0～0.5 秒 | 选择冰弹，先蓄力；0.25 秒后发射 |
| 第 2 回合 | 0.5～1 秒 | 锁定时间已在 0.45 秒结束，模型再次决策并立即开始新动作；上一发冰弹继续飞行至 0.85 秒 |
| 后续回合 | 每 0.5 秒 | 若每次所选技能的 `windup_ms + recovery_ms <= 500`，霜铃每回合都有决策机会 |

冰弹即使在新动作开始后仍未命中，也会继续按原弹道飞行和判定，不会被新动作替换或截断。

双方的锁定状态各自独立。霜铃仍在执行冰弹动作时，绯刃如果已经能够行动，就可以在回合开始时选择架刀、移动或攻击。

## 5. 冷却回合示例

`cooldown_turns = N` 表示：**施放后的 N 个回合内，不能再次使用该技能。**

例如，第 1 回合施放一个冷却为 2 回合的技能：

| 回合 | 该技能的冷却状态 |
| --- | --- |
| 第 1 回合 | 本回合施放，开始记录冷却 |
| 第 2 回合 | 不可再次使用 |
| 第 3 回合 | 不可再次使用 |
| 第 4 回合 | 冷却结束；若动作锁定已解除且资源足够，则可使用 |

冷却跟随回合推进，不随现实等待时间减少。角色处于动作锁定期间，回合仍正常推进，冷却也会相应减少。

## 6. 播放、暂停与回放

- **实时对局**：浏览器播放完本回合后，再请求下一回合。模型思考期间没有新的战斗时间推进。
- **手动暂停**：暂停画面播放和后续回合请求。已经发出的模型请求可以完成，其结果可能缓存在浏览器中。
- **回放倍速**：改变观看同一段战斗所需的现实时间，不改变记录里的动作、伤害、冷却或胜负。
- **回放拖动**：查看所选模拟时间的已保存状态，不重新请求模型，也不重新决定战斗结果。

页面中的秒数、技能阶段时长和对局时间上限都按游戏模拟时间理解；模型请求延迟按现实时间理解。

## 7. 配置与代码位置

| 项目 | 字段或位置 | 默认值或说明 |
| --- | --- | --- |
| 每回合推进时长 | `GameConfig.decision_ms` | 500 毫秒 |
| 每个模拟步时长 | `GameConfig.step_ms` | 50 毫秒 |
| 对局时间上限 | `GameConfig.time_limit_ms` | 60000 毫秒模拟时间 |
| 技能阶段时长 | 人物技能的 `windup_ms`、`active_ms`、`recovery_ms` | 按模拟时间执行 |
| 决策锁定时长 | `windup_ms + recovery_ms` | 不包含 `active_ms` |
| 技能冷却 | 人物技能的 `cooldown_turns` | 非负整数回合 |
| 回合与命中结算 | [backend/game/engine.py](../backend/game/engine.py) | `Arena.advance()` 推进一个回合 |
| 人物技能配置 | [configs/characters/](../configs/characters/) | 各人物的 `character.json` |

收益矩阵如何使用这些时序规则，见 [风险加权反事实推演与收益矩阵说明](counterfactual-planning.md)。相关运行与配置说明见 [README.md](../README.md)。
